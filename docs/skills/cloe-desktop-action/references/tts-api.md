# TTS Voice API

Covers three TTS-related capabilities: conditional TTS scheduling (delayed playback + cancellation on user confirmation), TTS audio file serving, and integration with the `generate_tts.py` script.

> The recommended way to have the character speak directly is `generate_tts.py --speak` (see [action.md](action.md)), which generates the audio and triggers it via the `/action` speak action. This document covers the underlying scheduling config and audio file hosting.

## 1. Conditional TTS Scheduling

When reminders and agent sessions trigger TTS, playback isn't immediate -- it's **delayed by a window** (3 seconds by default). If the user interacts within that window (e.g. opens the related panel), the TTS is cancelled -- avoiding redundant interruptions.

### Config Data Model

```json
{
  "conditional_tts": true,
  "tts_delay": 3000
}
```

| Field | Type | Description |
|------|------|------|
| `conditional_tts` | bool | whether conditional delay is enabled. When `false`, all TTS plays immediately (no delay, not cancellable) |
| `tts_delay` | number | delay in milliseconds (default 3000) |

### Read Config

```bash
curl -s http://localhost:19851/tts-scheduler/config
```

### Update Config

```bash
# Disable conditional delay, all TTS plays immediately
curl -s -X POST http://localhost:19851/tts-scheduler/config -H 'Content-Type: application/json' \
  -d '{"conditional_tts":false}'

# Change the delay to 5 seconds
curl -s -X POST http://localhost:19851/tts-scheduler/config -H 'Content-Type: application/json' \
  -d '{"tts_delay":5000}'
```

### Cancel Pending TTS

Cancels TTS that's still within the delay window and hasn't played yet.

```bash
# Cancel a specific source (sourceKey looks like "reminder:drink-water" or "agent:sessionId:turn-end")
curl -s -X POST http://localhost:19851/tts-scheduler/cancel -H 'Content-Type: application/json' \
  -d '{"sourceKey":"reminder:drink-water"}'

# Cancel by source type + id (cancels a specific reminder's TTS)
curl -s -X POST http://localhost:19851/tts-scheduler/cancel -H 'Content-Type: application/json' \
  -d '{"source":"reminder","id":"drink-water"}'

# Cancel everything pending
curl -s -X POST http://localhost:19851/tts-scheduler/cancel -H 'Content-Type: application/json' \
  -d '{"sourceKey":"*"}'
```

| Parameter | Description |
|------|------|
| `sourceKey` | the full source key; pass `"*"` to cancel everything |
| `source` + `id` | alternative: `source` is `'reminder'`/`'agent'`, `id` is the corresponding id |

> Note: `cancel` only cancels TTS that **hasn't played yet** (still within the delay window). Once playback has started, it can't be cancelled.

## 2. TTS Audio File Serving

Audio generated by `generate_tts.py` is written to `~/.cloe/audio_cache/`, then exposed via the `/tts/:filename` HTTP endpoint, for the character's speak action to play (Chromium needs to load audio via an HTTP URL, and requires Range request support).

### Reading Generated Audio

```bash
# Streams the audio back, supports Range (206 Partial Content)
curl -s http://localhost:19851/tts/hello_1719400000000.mp3 --output voice.mp3
```

Supported formats: `.mp3`, `.wav`, `.opus`, `.ogg`. The filename comes from `generate_tts.py`'s `--output`, typically formatted as `<text>_<timestamp>.<ext>`.

### Built-in Fallback Audio

The app ships with two pre-recorded audio files, used as a fallback for agent sessions when dynamic TTS fails:

```bash
# Turn-complete notification sound
curl -s http://localhost:19851/tts-fallback/turn_complete.mp3 --output turn.mp3

# Needs-user-decision notification sound
curl -s http://localhost:19851/tts-fallback/needs_decision.mp3 --output decide.mp3
```

## 3. Integration with generate_tts.py

The full "make the character speak" pipeline (see [action.md](action.md) for details):

```bash
# 1. Generate audio (writes to ~/.cloe/audio_cache/ and returns the filename)
python3 ~/.hermes/skills/creative/cloe-desktop-action/scripts/generate_tts.py \
  --text "Hello, I'm Cloe"

# 2. Trigger speak with the returned filename (audio_url points to the /tts/ endpoint)
curl -s -X POST http://localhost:19851/action -H 'Content-Type: application/json' \
  -d '{"action":"speak","audio":"hello_1719400000000.mp3"}'
```

The `--speak` flag automatically performs both steps above.

## Notes

- Config is persisted in `~/.cloe/tts-scheduler.json`
- `conditional_tts` mainly affects TTS for reminders and agent-sessions; TTS triggered by `generate_tts.py --speak` is immediate speak, and doesn't go through the scheduler
- Both `/tts/:filename` and `/tts-fallback/:filename` prohibit path traversal (filenames can't contain `/`, `..`, or null bytes)
- Clients receive `tts-scheduled` (TTS queued in the delay window), `tts-cancelled` (cancelled), and `tts-played` (played) messages via WebSocket
